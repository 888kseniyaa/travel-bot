# Telegram-бот для путешествий — этап 3

Сценарии первых этапов сохранены: география → интересы → выбор мест → изменение времени → подтверждение. Третий этап строит однодневный план для 1–6 мест: дата, начало и конец дня, подтверждённая стартовая точка, необязательная конечная точка, лимит ходьбы и фиксированный обед. Бот учитывает часы работы, сравнивает ходьбу с общественным транспортом, проверяет переходы на фактическое время и объясняет исключённые места.

## Установка и режимы

Python 3.10+, один процесс long polling, доступ к Telegram; для real — также к Google. В терминале в этой папке:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

Отредактируйте `.env` локально. Токен получите у [BotFather](https://t.me/BotFather). Не присылайте секреты в чат и не записывайте их в историю команд.

- `BOT_MODE=real` — режим по умолчанию. Требуются `TELEGRAM_BOT_TOKEN`, `GOOGLE_PLACES_API_KEY`, `PRIVACY_POLICY_URL`, `TERMS_URL`. Для Routes можно задать отдельный `GOOGLE_ROUTES_API_KEY`; иначе используется ключ Places.
- `BOT_MODE=demo` — явно выбранный тестовый режим. Нужен только `TELEGRAM_BOT_TOKEN`; Google не вызывается. Восемь мест Санкт-Петербурга и три района: Центральный, Адмиралтейский, Петроградский.
- `ROUTES_DB_PATH` — путь к SQLite с сохранёнными маршрутами, по умолчанию `data/routes.sqlite3`. Родительская папка и первая миграция создаются при запуске.

Отсутствие Google-ключа в real — ошибка настройки; автоматического переключения в demo нет. В каждом экране указан режим/источник.

```sh
set -a
source .env
set +a
python -m travel_bot
```

Приложение читает переменные окружения; файл `.env` сам не загружается. Для Windows используйте соответствующую активацию venv и настройки окружения PowerShell. Остановка — Ctrl+C. Не запускайте два экземпляра с одним токеном.

Секреты не входят в поставку: `.env`, файлы `*TOKEN*.txt`, `*KEY*.txt` и `secrets/` исключены в `.gitignore`. Игнорирование не удаляет уже отслеживаемые файлы из Git: если секрет ранее коммитили, исключите его и смените ключ. Программа **не читает** файлы с токенами `.txt`; ключ и токен используются только из окружения. Не включайте локальные секретные файлы в архив проекта.

## Настройка Google

1. Создайте/выберите Google Cloud project, включите **Places API (New)** и **Routes API**, а также биллинг.
2. Ограничьте ключи нужными API и исходящим IP. Можно использовать один ключ для обоих API или отдельный Routes-ключ через `GOOGLE_ROUTES_API_KEY`.
3. Задайте небольшие квоты на Text Search, Place Details, Compute Route Matrix и Compute Routes; настройте оповещения расходов. Внутренний лимит относится к одному подбору, а `/start` создаёт новый.
4. Сохраните ключ в `GOOGLE_PLACES_API_KEY`. Полный URL запроса никогда не содержит ключ: используется заголовок `X-Goog-Api-Key`. Сырые ответы, исключения и HTTP-логи не выводятся.
5. Перед использованием real предоставьте публичные страницы условий и конфиденциальности и укажите HTTPS-адреса в `TERMS_URL` и `PRIVACY_POLICY_URL`. Бот показывает их командами `/terms` и `/privacy`. Страницы должны описывать оператора/контакты, передачу географического запроса Google, работу Telegram и память сессии, а также включать необходимые ссылки на условия Google Maps и политику Google. Бот проверяет формат URL, но не достоверность/содержимое страниц. Размещение этих страниц не входит в задачу.

Настройки зависят также от страны биллинга и доступности сервисов. [Руководство по безопасности ключей](https://developers.google.com/maps/api-security-best-practices), [квоты и биллинг](https://developers.google.com/maps/documentation/places/web-service/usage-and-billing).

## География и точность

В real введите, например, `Paris, France` или `Montmartre, Paris, France`. Название района рекомендуется вводить вместе с городом и страной. Первый Text Search ищет территорию: запрос возвращает до пяти кандидатов, из них бот показывает до трёх с подходящим типом города/района и корректным `viewport`. Территорию требуется **явно подтвердить даже при единственном результате**. Можно отказаться и уточнить запрос. Страны, области верхнего уровня, объекты без подходящей территории и нераспознанные запросы не подменяются Санкт-Петербургом.

Поиск мест использует `locationRestriction.rectangle` с `low/high` из подтверждённого Google viewport. Это прямоугольник, а не полигон административных границ: соседние кварталы могут попадать внутрь, а нетипичный viewport — не покрывать весь район. Кандидаты географии могут зависеть от IP-смещения Google; до подтверждения места не ищутся. Бот не утверждает, что различает все одноимённые районы. Поиск категорий использует ограничение, а не `locationBias`, и не добавляет другой город в запрос.

Поведение параметров проверено по [Text Search (New)](https://developers.google.com/maps/documentation/places/web-service/text-search); автоматические тесты проверяют переданный прямоугольник. Пространственная точность конкретной живой выдачи Google пока не проверялась.

## Категории, карточки и ограничения выдачи

| Категория бота | textQuery | Google includedType | Оценка бота |
|---|---|---|---|
| Музеи | `museums` | `museum`, strictTypeFiltering=true | 120 мин |
| Парки | `parks` | `park`, strictTypeFiltering=true | 60 мин |
| Архитектура | `architectural landmarks` | отсутствует; текстовый категорийный поиск | 45 мин |

У Google нет универсального типа `architecture`. Результаты архитектурного поиска могут включать разные виды достопримечательностей; это поисковый интерес, а не подтверждённая классификация памятников. Поддерживаемые типы сверены с [Place Types](https://developers.google.com/maps/documentation/places/web-service/place-types).

На каждую выбранную категорию отправляется один запрос с `pageSize=5`. Полученные списки объединяются по Google `places.id`; совпавшему месту добавляются метки интересов. Для оценки времени используется первая категория в порядке музей → парк → архитектура. При обновлении уже заданные пользователем минуты сохраняются.

- До **15 уникальных мест** в подборе, страницы по **3 места** в real. Для одного плана можно подтвердить не более **6 мест**. Перелистывание локальное, Google `nextPageToken` не запрашивается.
- До **12 HTTP-попыток за подбор**, включая географию, категории и повторы. Обычный первый поиск: 1 запрос географии + 1–3 запроса интересов. Новый подбор начинает новый бюджет.
- Тайм-аут соединения 3 с, сетевых операций 8 с, каждой HTTP-попытки целиком 10 с. Не более одного повтора через 0,5 с при сетевом сбое/тайм-ауте и HTTP 500/502/503/504. HTTP 400/401/403/429 не повторяются автоматически.
- Для планирования выбранные места дополнительно обогащаются координатами и текущими часами работы через Place Details — не более одного запроса на место за расчёт. Неизвестные часы не блокируют место: бот показывает предупреждение.
- Карточки: имя, адрес (или отметка отсутствия), интересы, оценка минут и ссылка Google Maps, если она возвращена. Фактические описания не сочиняются. Фото и отзывы не запрашиваются.
- Время посещения — оценка приложения, не данные/статистика Google. Пользователь может изменить её; планировщик никогда сам не сокращает посещение.

## План дня и выбор транспорта

После подтверждения мест нажмите «Спланировать день». Дата ограничена сегодняшним днём и следующими семью днями; конец по умолчанию — 20:00, лимит ходьбы — 90 минут. Старт всегда подтверждается по варианту Google; финиш можно оставить у последнего места или указать отдельно. Обед занимает заданный интервал и не сдвигается.

До 15 минут бот выбирает ходьбу. Для 15–40 минут он сравнивает полное время вариантов и добавляет к оценке транспорта 5 минут за пересадку. Для более длинного пешего перехода предпочитает транспорт; если маршрут транспорта недоступен, проверяет ходьбу и предупреждает о длинном переходе. Из допустимых вариантов бот сначала максимизирует число посещённых мест, затем выбирает более раннее завершение, меньше дороги, ходьбы и пересадок. Непоместившиеся или закрытые места исключаются с объяснением пользователю.

На один расчёт выполняются две матрицы, WALK и TRANSIT, не более 49 элементов каждая, и до 12 проверок отдельных переходов. Транспортная матрица на время начала дня служит предварительной оценкой порядка; итоговые переходы запрашиваются заново на фактическое время отправления. Подробности конкретного перехода запрашиваются только по кнопке и не более одного раза для этого перехода в текущем расчёте.

После успешного расчёта итоговый экран содержит кнопку **«Открыть маршрут в Google Maps»**. Она формирует локально один Maps Directions URL из стартовой точки, посещаемых мест в порядке плана и отдельного финиша, если он задан. Если Routes API отклонил или не смог выполнить расчёт, бот всё равно показывает кнопку **«Открыть выбранные места в Google Maps»**: точки передаются в порядке выбора пользователя, а рядом явно указано, что маршрут и расписание бот не рассчитывал. Новый запрос Places или Routes для любой из ссылок не выполняется, API-ключ в неё не добавляется. Единый `travelmode` не задаётся: Google Maps строит собственный вариант, поэтому линия, время и способы перемещения могут отличаться от смешанного WALK/TRANSIT-плана бота. URL длиннее 2048 символов не отправляется. При более чем трёх промежуточных точках бот предупреждает, что некоторые мобильные клиенты могут открыть не все точки; другие клиенты также могут применять собственные ограничения. Maps Demo Key предназначен для ограниченного прототипирования поддерживаемых API и не нужен для универсальных Maps URLs.

## Сохранённые маршруты

После успешного расчёта маршрут автоматически сохраняется в SQLite. Повторная обработка того же результата не создаёт дубль. К списку ведут кнопка **«Мои маршруты»** на стартовом и итоговом экранах и команда `/routes`. Список показывает пять записей на страницу; доступны открытие, переименование и удаление. Просмотр списка не удаляет незавершённый подбор. `/delete_my_data` удаляет все маршруты пользователя после отдельного подтверждения.

На пользователя допускается до 20 маршрутов. Записи старше 30 дней удаляются перед чтением и сохранением; ровно на границе 30 дней запись ещё доступна. При достижении лимита текущий рассчитанный план остаётся в памяти, но для нового сохранения нужно удалить старый маршрут. Ошибка SQLite также не отменяет расчёт.

В базе хранятся Telegram user ID владельца, собственное название, исходные пользовательские запросы, параметры дня, пользовательские длительности, Place ID, категории, порядок мест и координаты на срок записи. Не сохраняются username, ключи, токены, Google-названия, адреса, часы, сырые ответы, транспортные шаги и сырые результаты Routes. При открытии бот получает актуальные данные Google и заново проверяет переходы в сохранённом порядке; результат может отличаться от первоначального. Запись остаётся неизменной, если обновление не удалось.

SQLite работает в WAL-режиме. Для резервной копии сначала остановите бота, затем скопируйте файл, указанный в `ROUTES_DB_PATH`, в защищённое место. Восстановление выполняйте также при остановленном процессе. На этапе 5 локальный путь должен находиться на постоянном диске либо репозиторий нужно перенести в управляемую базу. Файлы `data/*.sqlite3`, `-wal` и `-shm` исключены из Git.

Перед пилотом обновите публичную политику конфиденциальности: опишите хранение Telegram user ID, пользовательских запросов и параметров маршрута до 30 дней, обновление данных через Google и команды удаления. Place ID разрешено хранить отдельно, но этот MVP удаляет всю запись по общей 30-дневной политике. [Правила Places API](https://developers.google.com/maps/documentation/places/web-service/policies), [правила Routes API](https://developers.google.com/maps/documentation/routes/policies), [условия Google Maps Platform](https://cloud.google.com/maps-platform/terms/maps-service-terms).

## Поля, атрибуция и хранение

Используются Text Search, Place Details, Compute Route Matrix и Compute Routes. Запрашиваются только поля, нужные экрану и расчёту:

- Территория: `places.id,places.displayName,places.formattedAddress,places.types,places.viewport,places.attributions`.
- Места: идентификатор, имя, адрес, координаты, Google Maps URI и атрибуции.
- Детали выбранных мест: координаты, часовой пояс, текущие периоды работы, URI и атрибуции.
- Матрицы: индексы, статус, расстояние и длительность; переходы: длительность, расстояние, предупреждения и шаги транспорта. Навигационные инструкции запрашиваются только по запросу пользователя.

Wildcard, отзывы, фото, рейтинги, генеративные сводки и несуществующее поле длительности не запрашиваются. Часы запрашиваются только для выбранных мест перед планированием. Выбранные поля относятся к **Text Search Pro** (оплата определяется самым высоким запрошенным SKU). На проверенной 8 сентября 2026 странице глобального прайса: 5000 бесплатных событий в месяц, затем $32 за 1000 в первом платном диапазоне; региональные тарифы и изменения проверяйте в [официальном прайсе](https://developers.google.com/maps/billing-and-pricing/pricing). Повторные запросы могут влиять на расходы.

Каждое real-сообщение с данными имеет текстовую атрибуцию **Google Maps**, подходящую для компактного текстового интерфейса. Возвращённые `attributions` сторонних поставщиков сохраняются и показываются рядом с данными. Ссылки мест ведут в Google Maps; карты других поставщиков не используются. Превью ссылок выключены. Длинные ответы разделяются на сообщения с учётом лимита Telegram; кнопки — на последнем.

Содержимое Google не сохраняется на диск и не используется как постоянный кэш: только текущая сессия в памяти, до 30 минут от `/start`. Проверка срока выполняется при обращении и фоновая очистка раз в минуту. Выбор тоже истекает; `/start` и перезапуск очищают его раньше. Google place ID освобождены от общих ограничений кэширования, но здесь даже они не записываются постоянно. История сообщений в Telegram существует отдельно и очисткой памяти бота не удаляется; это должно быть отражено в политике владельца. Не трактуйте срок 30 минут как универсальное разрешение Google на кэш: здесь это ограничение оперативного состояния текущего диалога. Правила использования и региональные условия обязан соблюдать владелец приложения. [Политики Places и атрибуция](https://developers.google.com/maps/documentation/places/web-service/policies).

## Надёжность и устройство

- `day.py`, `planner.py`: модели параметров/расписания и детерминированный локальный подбор порядка.
- `routes.py`, `planning.py`: ограниченные запросы Routes, повторная проверка переходов и защита от устаревших результатов.
- `route_map.py`: чистое формирование одной ссылки Google Maps без сети и ключа API.
- `saved_routes.py`, `route_repository.py`: строгий формат разрешённых данных, SQLite и миграции.
- `saved_route_service.py`, `saved_route_flow.py`: автосохранение, обновление текущих данных и Telegram-управление.
- `places.py`: модель Place, оценки бота и DemoSource.
- `google_places.py`: GoogleSource, нормализация, территория, безопасные ошибки, бюджет запросов.
- `state.py`: состояние по `(chat_id, user_id)`, срок жизни, выбранные Google ID и минуты.
- `dialog.py`: синхронные переходы диалога и представление. Сеть не вызывается из real-переходов.
- `search.py`: асинхронное получение результатов, атомарное применение или сохранение предыдущей выдачи при сбое.
- `telegram_app.py`: адаптер Telegram и фоновые задачи поиска/планирования.
- `settings.py`, `__main__.py`: проверка внешних настроек и запуск.

Telegram-изменения обрабатываются последовательно. HTTP-запросы выполняются фоновыми asyncio-задачами, не блокируя `/start` и других пользователей. Один поиск на сессию; повторные нажатия не создают второй запрос. Завершение проверяет исходный объект сессии и конкретную операцию: старый ответ не изменяет новый подбор. Старые кнопки отклоняются по session/revision. Google ID не помещаются в callbacks — только индекс места в текущем состоянии. При новой выдаче меняется revision.

Сбой Google не подменяется demo, ошибки ключа/квоты/тайм-аута объясняются без чувствительного тела ответа. Частично выполненный поиск не заменяет предыдущую выдачу. При сбое отправки Telegram состояние сохраняется; `/resume` восстанавливает текущий экран. В группах подбор не создаётся. Один процесс, память без постоянного хранения и без защиты от многопользовательского платного злоупотребления: для публичного масштабирования нужны отдельные ограничения.

## Проверки и ручной сценарий

Автотесты по умолчанию не используют настоящие ключи или платную сеть:

```sh
python -m unittest discover -s tests -v
python -m pip check
```

Тесты используют временные SQLite-файлы и фиктивные ответы Places/Routes без платной сети. Они покрывают миграцию, повторное открытие базы, срок и лимит хранения, идемпотентность, изоляцию владельцев, версии записей, повреждённые данные, управление маршрутами, выбор режима и Telegram-сценарии.

Ручной real-прогон:

1. Настройте ключ, биллинг и публичные политики. Запустите `BOT_MODE=real`. `/start` → `Paris, France` → подтвердите правильную территорию. Для неоднозначного района попробуйте уточнение; не выбирайте чужой город.
2. Музеи + парки + архитектура → поиск. Проверьте имя, адрес, атрибуцию, ссылки Google Maps и видимую территорию. Пустой результат позволяет сменить интересы/географию.
3. Выберите место, перейдите на следующую страницу, выберите ещё одно, вернитесь назад. Выбор не должен исчезнуть. Повторное нажатие снимает выбор.
4. Измените длительность, подтвердите список и нажмите «Спланировать день». Введите дату, время, старт; подтвердите найденную точку. Выберите финиш, лимит ходьбы и обед.
5. Проверьте расписание, режим и длительность каждого перехода, пересадки, ссылки, предупреждения и объяснение исключений. Нажмите «Открыть маршрут в Google Maps» на телефоне и в браузере: должны сохраниться старт, порядок посещаемых мест и выбранный финиш. Сравните геометки, не ожидая совпадения линии, времени и режимов с расчётом бота. Для четырёх и более промежуточных точек проверьте предупреждение и фактическое поведение обоих клиентов. Для проверки резервного варианта временно используйте ключ без доступа к Routes API: после понятного сообщения об ошибке должна появиться кнопка «Открыть выбранные места в Google Maps», а точки должны идти в порядке выбора.
6. Вернитесь через `/resume`: ссылка должна оставаться доступной для текущего результата. Откройте подробности одного перехода; измените параметры и пересчитайте.
7. Во время расчёта отправьте `/start`, затем нажмите старую кнопку: новый подбор не должен измениться. Второй аккаунт должен иметь независимое состояние.
8. `/terms`, `/privacy`; после 30 минут или перезапуска требуется новый подбор. Demo сохраняет сценарий выбора мест; планирование Routes доступно в real.
9. Перезапустите бот. Выполните `/routes`, откройте сохранённый маршрут и проверьте сообщение об обновлении данных Google, расписание и кнопку карты. Переименуйте маршрут, затем проверьте удаление с отменой и подтверждением.
10. Начните новый подбор, откройте «Мои маршруты» и вернитесь: незавершённый выбор должен сохраниться. `/delete_my_data` должен запросить подтверждение и удалить только маршруты текущего пользователя.

Живая проверка Telegram и Google на этом этапе **не выполнена**. Автотесты проверяют код на подменённых ответах, но не реальный ключ, биллинг, расписания транспорта и региональную выдачу. Публикация и развёртывание не проводились.
